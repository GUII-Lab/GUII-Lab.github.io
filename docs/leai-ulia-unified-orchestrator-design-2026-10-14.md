# Ulia：统一 orchestrator 与可审查的判定理由

状态：最终 v13 本地六轮和独立逐条审查通过，已部署 guiidata v87 与限定五文件前端发布，并为 cmpm80h-wi27 新增两份 v3 问卷。原 v10 HOLD 和线上 v86 失败日志保留；不表示全部 schema 或生产六轮已验收。

## 目的与已确认方向

研究员需要在真实对话中、通过 resume link 复访时，看到 AI 为什么把一段回答判为满足、部分满足、拒答或无法回答，并能把这个理由与原文和 schema 对照。学生仍应得到自然、能因上下文调整的采访，而非被迫经过固定细问。

用户选择：把现有“答案评估 → 对话生成”两次顺序调用合并，由一个 AI 步骤结合完整上下文提出答案判断、必要状态修改、下一步和学生回复；增加简短的逐项 justification。用户认为当前拆分和过多约束可能限制灵活性。这是待比较验证的架构假设，现有日志没有证明拆分本身是所有误判的原因。

候选采用这一方向。继续双步骤只添加理由不满足合并要求；每回合固定增加另一个 reviewer 会增加任务量和延迟，本方案不采用。Justification 首先提供可审查证据；是否降低误判率由相同输入回放验证，不预先承诺。

## 每回合的新流程

学生消息 → 程序读取冻结 schema、当前状态和会话历史 → 一次统一模型判定 → 程序检查结构和数据一致性 → 同一事务保存学生消息、AI回复、状态和debug事件。

正常回合只调用一次模型。结构或确定性规则不通过时，允许一次有具体错误说明的修正调用；沿用共享24秒预算，最多两次模型请求。失败不能转成学生的unknown，不能推进状态，也不能重复保存。暂不可用时保留正常重试入口。

取消独立 assessor/facilitator 和候选 allowed_actions 枚举列表。模型直接根据 schema 和上下文提出动作，程序继续检查动作是否跳题、是否重复关闭后追问等确定性条件。

取消“每轮必须重新逐项报告全部已出现题目”。正常只报告当前题及本轮确有新信息的其他题；没有变化的历史题由程序保留原状态。完整历史仍作为上下文提供，学生可以澄清、一次回答多题、修订早先回答，或边回答边提问。

不再要求模型抄回内部任务编号。请求ID、输入指纹、协议版本、调用与结果的关联及提交前版本检查由程序持有，阻止过期结果覆盖新状态。结构完整不等于语义正确：取消全历史清单后，隐式多题关联遗漏仍需用回放和独立审查评估，不宣称彻底消除。

## 判定输出与 justification

复用现有统一 TurnProposal 思路，保留必要的更新、证据和动作字段，添加两种可读理由：

1. 每个实际更新项的 `justification`：建议1–3句、最多600字符，解释原文如何支持该题的status、已满足部分、关闭部分及实际改变的coverage。沿用结构化 `item_id`、exact evidence、`satisfied_components`、`closure`，不再复制一套完整题目清单或每题重复历史。
2. 每回合的 `action_justification`：最多400字符，解释为什么现在继续追问、解释题意、进入下一题或准备review。纯澄清可以没有答案更新，但必须有动作理由及最新学生证据。

理由应当是简短、可核查的判定说明，不要求隐藏推理过程、长篇自我分析或自报置信度。每项理由必须能与它的题目要求及结构化原文证据对应。不能用一句泛泛的“回答充分”替代依据。

例如，P2收到“Skip this question. I refuse to answer either part.”时：

- P2状态declined；answer未满足；因refused关闭answer；理由说明学生明确拒绝当前问题。
- P1保持之前的负面实践答案及not_applicable覆盖，不能借P2的拒答宣称P1解释了决策过程。
- 动作理由说明当前题因拒答已关闭，所以进入下一题。

M3第一次、且唯一一条回答是拒答时：answer不能标为已满足。若之前已有有效答案，学生只是拒绝再添加细节，则保留已有有效答案；这两个情形必须分开测试，不能用“closure与satisfied绝不能并存”的粗规则误删内容。

## 灵活性和仍需保护的边界

允许模型自由组织解释、承接和聚焦的追问；按语境判断而非用关键词分类。明确负面实践可以是有效答案；有实质原因的不确定回答可以保留；不强求具体事例；足够的评分和解释可以直接推进；学生可以在review前修订。

保持原始schema的主问题措辞、题序、量表和作者规定的最大额外追问次数。不能把数据保护当成采访脚本，也不能为增加自由度改写原研究工具。

历史修订的默认范围是当前题。学生实际回指旧题、纠正共享内容或一次涉及多题时，允许跨题更新，并为每个变更说明最新原话为何与该题相关。不能要求学生必须说内部题号；应用程序也不以关键词匹配假装理解修订意图。

程序检查题号、引用真实性、类型、分值范围、所需证据、事务/版本/重试，以及可由结构判定的矛盾。它不能仅凭有一段justification就证明语义正确；本方案不把同一个模型的理由当作独立验证。跨题关联与满足程度是本次候选重点验收内容。

## 理由保存与研究员界面

每回合把受校验的判定理由、相关题号、原文引用和动作理由，存入现有debug事件 `metrics` JSON 中的受限 `decision_explanation` 子对象；不新增数据库列。它是显式输出的判定说明，单独于模型/耗时指标显示，不记录隐藏推理、完整提示词或凭据。

保存成功时，这份说明必须来自实际提交的同一份proposal，不能在事后另调模型生成解释。失败时保持before==after；若已有结构合法的判定说明，可记录为“未提交的提议”并附拒绝类别，绝不显示成已保存结果。无法解析/不完整的理由明确标为不可用，不从原文补造。

聊天每条AI回复的 `Recorded schema state` 先显示当前题/阶段、实际动作及状态变化，再显示“判定依据”，用原文和理由帮助研究员审查。保留整体当前状态、历史快照和JSON导出；不常驻展示JSON，不把理由插入学生正文或Analyzer历史。开场或旧记录没有理由时显示未记录，不能推断历史理由。

移动端采用原有单列换行方式，理由完整可展开；保持无省略截断。离开当前消息再返回时，读取同一服务器记录。Debug关闭时不保存这些新增研究员说明，学生流程仍可运行。

## 兼容和作用范围

新增执行协议版本3及两份additive Ulia schema版本，题目内容保持v2的原Doc修正结果；版本变化表达执行/trace合同变化，不是重新改量表。已冻结v1/v2会话仍按各自协议处理与显示，不能在旧会话上默默切换新算法或补理由。新候选通过后才另行安装新版本供新会话使用。

后端需涉及统一provider入口/合同、协议分流、执行校验、debug事件投影与相应测试；前端主要涉及 `LEAI/leai-debug.js` 和实际加载入口的缓存版本。实现计划在该设计获批后列出精确文件和迁移/兼容检查。保持当前分支，不改其他Advisor工作，不整体推送后端仓库。

## 验收：先匹配输入，再真实浏览器

1. 对同一组固定schema、相同起始状态和学生原文，分别回放v86与统一候选；单列执行失败、独立错误引入次数、受影响会话和后续持续状态。重试不是独立样本。保留原始失败，不把类别数当成错误率。
2. 必测CR108/P2拒答不改P1、CR118首次拒答不满足answer；同时测已有有效回答后拒绝补充、真正的历史纠正、未提题号的回指、一句回答多题和共享内容撤回。确认防串题没有封死合法修订。
3. 回放导致九次失败的两段原始输入，确认不再存在模型抄内部编号的要求；版本过期、同请求重试、并发和重复请求的数据保护仍通过。
4. 保留原Doc0/6端点、完整0–6频率标签、只评分/只反思、负面实践、纯澄清、混合不确定但有实质内容、无法回忆/拒答及停止探问等基线。
5. 每个实际改变的题目和每个动作均有同回合理由、真实引用和状态对应。独立审查分别判断“结论正确性”和“理由是否支持结论”，不能因理由写得流畅就判通过。工程测试不证明自然语言理由真实反映模型内部机制。
6. 再用真实页面完成两schema×认真/rude/没想法六轮，在全部结束后核对每条消息、全部JSON和理由、debug面板及实际导出。浏览器Terms按当次范围处理；研究同意关闭；遵守用户不截图/录屏要求。
7. 本阶段先交付本地候选和证据。当前生产v86和六轮失败记录保持原样；新的发布、安装或生产会话清理以具体候选和对应授权为准。本设计本身不表示已发布或测过。

## 自审

没有用放宽量表、猜分数或跳过数据保护来换取流畅；没有固定第二个语义agent；没有声称理由必然降低错误；没有禁止真实历史修订；没有把原有有效内容与首次纯拒答混为一谈；没有把旧会话理由补写成当时记录。验收仍需证据，当前结论仍为HOLD。

## v11 本地完整审查后的收敛

v10 六轮共160条消息、82个事件已逐条审查，保留原失败证据。修复不改变原始研究题目：评分追问由程序重现该题原文和原量表，避免模型把“检查某种影响”改成“这种影响发生多频繁”；准备review时使用涵盖有效回答和合法关闭的真实完成说明，不声称所有部分都已提供。其余澄清、反思追问和历史修订仍由统一模型结合上下文提出。

判断应针对原题所问行为，不能把相关话题或问题自觉当成行动已经发生；理由必须保留might/not sure等限定。不能从“没有某个具体例子”推断一般做法或频率都无法回答，可以进行一次不要求该例子的中性追问。已满足标记只能依靠仍有效的原证据或新内容；撤回全部原证据后，仅有不可回答边界不能继续算提供了答案。所有类别的关闭都遵守这项证据规则。

这次修复有确定性失败回归与真实新六轮，后续验收以新六轮完整结果为准，不能回写v10理由或把其HOLD改成通过。
