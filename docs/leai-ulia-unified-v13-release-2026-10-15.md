## What changed

Protocol 3 combines assessment and dialogue into one normal model call. A rejected draft gets at most one repair within the shared 24-second deadline. The actual model remains `gpt-5.6-luna`. The server owns request, input and version binding; the model no longer echoes an internal assessment identity or reports every unchanged historical item each turn.

Every proposed item update and next action includes a bounded justification. The committed explanation, original student quotes, supplied components, closure and coverage are saved with the same debug event. A rejected proposal is distinguished from a saved decision. The existing chat/resume debug panels show readable state and reasons; JSON remains an export. No schema history was added to the Analyzer. Teacher course authentication and the existing course debug setting remain authoritative; default off, only `cmpm80h-wi27` enabled.

The final output schema is compiled from the actual frozen instrument: valid item/target IDs, native response kind, authored numeric scale, component names and required object shape. Contextual interpretation remains with the unified model. These constraints prevent irrelevant text/Likert shapes without banning genuine historical corrections, multi-item answers or useful uncertainty.

The repair also preserves the original statement and scale when asking for a missing rating, distinguishes awareness of a problem from the behavior the item asks about, and distinguishes inability to recall a specific example from inability to answer about general practice. Supplied components must have surviving supporting evidence after withdrawal. The completion notice accommodates both valid answers and legitimate closures.

## Retained failed trials and rulings

The original unified v10 six remain HOLD: 160 messages and 82 events exposed M3 construct/sufficiency drift, an overbroad E3 no-example closure, and withdrawn evidence incorrectly retaining supplied status. The v11 batch completed six but a fixed-input withdrawal replay exposed a nullable component-array contract. V12 corrected that array but only five conversations completed; the rude Likert run failed three requests because the generic output shape allowed `likert: null` and irrelevant component choices. V13's protocol-shaped output removes those irrelevant alternatives; the final six all restarted on that unchanged version.

An original v12 one-off diagnostic JSON file was accidentally overwritten by a later v13 diagnostic writer. The retained evidence note identifies the overwrite; failed database events, original error log and tool excerpts remain. The replacement JSON is labeled v13 and is not claimed to be the original v12 response.

Earlier v11 browser transport stalls were preserved and resumed against the same sessions after replacing interception with a private served API constant. They were not backend/model failures. The earlier canonical snapshot copier omitted `scripts/`; this was our verification setup error, corrected in the complete final 1,994-test snapshot. A separate attempted baseline class lookup failed because that class was absent; it is not evidence reproducing an unrelated super-MRO error. Neither issue is used to waive a failing final suite.

One minor limitation is deferred: the v3 missing-rating renderer says “frequency rating” even for a different custom native Likert scale such as agreement. The compiler preserves that scale's actual values/labels, but the generic wording is unsuitable. Both released Ulia instruments use frequency, so this finding does not block their scoped release. Do not claim general semantic acceptance for arbitrary other Likert instruments. A second minor observation is one stray Korean token in an otherwise English researcher justification in a fixed replay; its item mapping, evidence and conclusion are correct, and the student reply is English. It is retained as a readability observation without another prompt change. No hook ignores or unrelated design fixes were added.
